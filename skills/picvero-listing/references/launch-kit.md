# 默认交付：电商套图与文案

主入口收到商品照片、没有更具体的要求时，先按 [品牌与批量](brand-and-batch.md) 自动归类本次全部商品，再逐款执行本页。目标是让卖家一次收到完整、醒目且能继续使用的上新素材。简短说明识别出的款数与交付范围后直接制作，不停在分组、方案或首张样图等用户批准。

**默认数量按商品款数计算，不按照片张数计算。** 同款多张照片共用一套；不同款每款完整五图＋文案＋HTML。三款商品默认三套、十五张独立图，不能把五张图分摊给三款，也不能只做一款代表。每款独立策划商品特征、镜头和适合的风格，已有店铺规范适用时共用。明确只做部分款、指定数量或产物的要求优先。

后续每件新商品都按 [跨品类完成度标准](visual-direction.md) 执行本页。沿用同等的设计投入、镜头变化与完整交付，根据商品重新决定表达；案例中的品类、配色、口号与布景不成为通用模板。

## 套图：默认五张独立图片

先看全部商品原照，按 [多角度与多图参考](multi-view.md) 内部确定整套视觉方向、逐图镜头、信息和文案，再调用图片工具。通常按以下五个图位交付，比例默认 1:1；比例是制作选择，不是平台规则。用户指定数量、用途和品牌时优先遵从。

| 图位 | 第一眼要传达的内容 | 画面选择 |
| --- | --- | --- |
| 主视觉 | 商品是什么，为什么吸引目光 | 大主体、鲜明光影与空间层次，可配简短中文主题；具备一张完整广告主视觉的完成度 |
| 纯净展示 | 看清商品本身 | 无叠加文案，简洁背景、自然接触阴影，保留商品原有标识和成色 |
| 核心特点 | 一个有依据的卖点或设计特征 | 商品与短标题形成清楚层级，用构图、色块或准确标注解释该特点 |
| 场景氛围 | 商品适合出现在哪种情境 | 可信且有美感的场景，商品依然突出；道具不暗示随货附赠 |
| 设计解析／购买信息 | 补充一个新的、能确认的信息 | 有细节实拍就用真实局部，有参数就用参数图；资料少时用不同景别或方向解释可见设计特征，推演视角按实际标注 |

默认交齐五张，通常至少三种明显不同的观察方向或商品姿态，并组合广告、棚拍、场景或编辑排版等表现方式。第五张的具体表达随资料变化，不拿无依据的背面、微距纹理、内部结构、尺码或性能充当卖点证据。单图可推演新角度，不因只有一张原照就锁死全套机位。若商品照片确实无法支持五个有区分的图位，合并缺乏依据的内容并简短说明实际数量，继续完成全部能做的图片和文案。不能默默退回只交一张。

审美默认采用 [视觉设计](visual-direction.md) 中的商业主视觉标准：商品鲜明、主次明确、场景有层次、不同图位有明显变化。第一张应有鲜明设计，不自动套用“浅底＋柔光”的保守方案；纯净展示图承担看清商品的任务。短标题可以表达审美感受，产品优势必须有事实来源。低清原图不要求虚假超清纹理，保持原有鞋型、器型、部件和标识优先。

## 文案：与套图同步完成

按 [文案与详情](listing.md)，用同一份商品事实输出：

- 三个可选商品标题：清楚的通用标题、设计特点标题、适合展示的简短标题。
- 三到五条有依据的卖点；资料少时只写可见特征，不用空话补足条数。
- 一段商品描述，以及每张营销图对应的短标题与说明。
- 需要卖家补充的品牌、材料、尺寸等资料，单独列出；不把“待填写”塞入成图。
- 使用本次真实输出图片的详情页 HTML 草稿；手机与桌面均可读，图片与文字共同形成完整阅读顺序。

默认沿用用户语言，不额外制作多语言图片。套图尚在生成时可以完成文案和页面结构；图片全部返回后再填真实文件，不用占位图冒充结果。

## 每张一次，整套连续完成

每个图位默认 `max_renders: 1`，一次内置图片调用产出该图位的第一版。五个独立图位意味着五次不同内容的调用；不能把同一张图的三轮修改当成三张套图，也不把一张五宫格代替五张独立商品图。

不先生成一张试方向、不自动出几个风格让用户选、不因“还能更好看”反复抽图。第一次调用前把布局、准确文字和商品不变项写清；原图细节不足时避免虚构微纹理与事实文案，按多角度约定安排并标明推演视角。已返回的图按 [审核](review.md) 快速对照一次并保存；没大问题直接交付，不展开长报告或逐个纠结细纹理。重大问题简短指出，继续其他图位和文案，不重新生成，也不等待用户确认。

只有用户明确要求修改某张时，才按指定范围制作新版本；修改后不再自行追加微调。原图无法证明的细节不会因多生成几次变成事实。工具失败就记录缺失图位，完成其余交付，不把空文件或失败图片当作已完成。

## 一次交付完整成果

按 [最终回复格式](delivery.md) 交付：完成标题、回复内“大图＋可切换缩略图”展示区、加粗的完整 HTML 展示页入口、一句实际交付摘要、素材下载与文案链接。只有本次确有待核对或未完成事项时才补一句说明；不把内部分析、逐次审图日志和提示词当作产品交付主体。

用 [运行记录](runtime.md) 保存原照、计划、各张输出与检查。可将运行器 export 的图片预览放在完整交付目录的子目录，再加入 `商品文案.md`、`详情页.html`，最后打包整个交付目录；核对压缩包包含图片和两份文稿，链接使用相对路径，解压可用。多款按 [交付格式](delivery.md) 保留每款独立目录、文案和详情页，再提供汇总 HTML 与整批 ZIP。未知或失败状态随图保留：`--drafts` 仅用于交付带状态的候选，不等于审核通过。没有用户选择时保持未选用。

主入口默认做套图和文案；单图、翻译、只审图、只写标题等明确要求仍按其实际范围执行。
