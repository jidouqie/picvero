# 文案与详情编排

适用于已有商品信息的标题、卖点、描述、参数整理，以及将用户已有图片排成详情页草稿。主入口默认按 [整套交付](launch-kit.md) 把文案和详情页与套图一同做完；明确只写标题或只做图的请求按其范围执行。Codex 直接完成文本与 HTML，不需要额外 API。

只用已确认或可靠观察的事实。说明品牌／材质／尺寸／认证等缺项，卖点图和文案使用同一份商品资料。不得编造销售量、评价、折扣原价和 A/B 测试结果。

按用户指定的语言、渠道和语气写；未指定平台则输出通用草稿。平台限制以已核对的资料或用户给定要求为准，说明规则覆盖范围。

详情页组织顺序可以是：商品全貌、使用场景、核心特点、真实细节、规格、售卖包含物。根据材料调整，不凑满无依据的模块。

已有套图时沿用其 [图位计划](marketplace-suite.md) 与商品事实：商品名和具体特点承担主要说明，场景文案承担氛围，参数/对照承担有依据的选择信息。避免每个详情模块重复同一句情绪标题。

HTML 使用本地已有图片和内联样式，适合预览与后续修改。主入口完整交付时，它是最终回复中“打开完整展示页”的主入口：集中呈现图片与商品介绍，支持电脑和手机阅读、图片放大与原图保存；最终回复另有 [可切换套图预览](delivery.md)。它不等于淘宝等后台接受的任意 HTML，也不是已经完成上架。需要新商品位图时才进入图片工作流。

交付可复制文案和本地文件。用户只要写标题时直接交付标题，不能强制要求图片、初始化整套任务或索取平台账号。
