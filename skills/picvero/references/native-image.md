# Codex 原生图片工具

## 能力识别

查看当前会话实际提供的工具及其说明，使用宿主内置 image_gen 或明确同等的生图／改图能力。内置 imagegen 技能可提供宿主操作规范；若可用，按宿主要求读取。不能凭技能名字推测工具存在。

不用 OPENAI_API_KEY，不运行图像 API 客户端，不读取 Codex 认证文件，不使用浏览器登录其他生图网站。也不使用本地脚本直接调用不存在的“内置生图接口”。

## 输入与调用

1. 本地原图先用会话图片查看工具检查。仅有附件时使用当前工具支持的附件引用。
2. 明确哪张是编辑目标、哪张是商品事实参考、哪张只是构图／场景参考。多图先按 [多角度约定](multi-view.md) 识别对应关系，每个镜头优先传最接近目标角度和能补充结构的原照，不默认只传第一张。
3. 参数按当前工具文档填写。当前宿主若支持 referenced_image_paths，则对已查看的本地图片传真实路径；若只支持最近图片引用，采用能够覆盖目标的最小范围。不要同时混用互斥的引用方式。
4. 改图把“改变什么”和“必须保留什么”写清。保持产品外形、可见部件数量、印刷文字、图案位置、颜色与售卖数量。不要删除产品自带品牌标识来满足“无叠加 Logo”。
5. 每个独立图位默认只调用一次；先把构图、准确文案和商品不变项定好，不先生成试方向。五张套图是五个不同图位各一次，不是同图的五轮修改或一次生成五宫格。批量仍由当前 Agent 遍历图位，不改用 CLI、另付费 API 或伪造并发接口。
6. 工具生成之后读取返回的真实文件位置或宿主交付结果。若有本地路径，检查存在后复制至任务目录；不能猜测 output.png 已生成。复制时保留原文件。
7. 快速对照一次；没有大问题直接交付，有大问题简短指出。工具已经展示完整结果时不重复打开查看，不因细节差异重生成。只有用户明确要求修改时才用原图与修改目标执行其要求，不自行追加微调。

只有工具返回图片才算图片产出。遇到只有预览、无法保存的环境，明确保存限制；继续交付实际可用的图片，不能把说明文本改扩展名充当位图。

## 制作规格

比例与分辨率可以作为制作要求，但不能把它们当作工具未提供的强制参数。实际像素与格式以结果检查为准。透明底应检查实际透明像素；“有 alpha 通道”不足以证明背景透明。

不要用代码绘制一个简化商品来代替商品摄影。尺寸、格式、精确局部编辑和确定性排版遵循当前宿主规则；如需某项额外能力，应先说明受限部分，不静默转向付费服务。

## 简短提示结构

- 任务／图位：为什么做这张图。
- 输入角色：图 1 是原商品；图 2 是当前修改目标或场景参考。
- 商品不变项：具体可见结构、文字、图案与数量。
- 可改项：按任务改变机位、商品旋转／摆放、使用姿态、景别、背景、光线和已确认的叠加文字；只换背景或翻译时保留原构图。
- 构图与比例：与实际用途对应。
- 依据与推演：明确每个原照支持的部分和新角度的推演范围；多角度任务要求重新取景，避免“保持原机位／姿态”的冲突提示。未知尺寸、功效、认证和标签文字不猜写，推演结构不当作事实证据。

不把完整内部推理发给图像工具；只传清楚的制作规格。
