# 共用工作约定

这里的图片执行者是 Codex 当前会话的内置图片工具。使用本机文件、Codex 看图与文本能力；不索取任何第三方生成平台账号或 API Key，也不访问作者后台。

## 开始任务

先采纳用户已有的商品、图片数量、平台、语言和风格要求。只问阻止正确交付的缺项；缺平台时不默认美国 Amazon。只要求一张图就做一张，不自动追加套图、模特或视频。

主入口被调用而用户只给商品照片、没有额外要求时，按 [意图入口](intent-entry.md) 自动归类本次全部商品，对每款执行 [整套交付](launch-kit.md)：默认各五张图、完整文案与详情页。发几款就完整做几套，同款多照合并参考，不停在代表商品。子技能按自身用途执行；当前明确要求和待续任务始终优先。

图片任务先读 [原生图片工具](native-image.md)。图片暂时不可用时，说明受阻的图像环节，继续用户需要的策划、文案或整理；不声称已出图、不偷偷改走 API。

区分输入角色：商品正面、背面、细节、售卖配件、风格／场景参考、人物参考、参数文档。款式不同的图按 SKU 分开。参考场景里的商品不是当前商品的事实依据。

## 事实与制作方案

把可见事实、用户／文档确认的参数、未知项、视觉选择分开。容量、成分、尺寸、认证、承重和功效不能从外观猜测后填成事实。照片中读不清的型号不要补字。使用 [商品与图位](product-and-shots.md)。

套图与换视角任务按 [多角度与多图参考](multi-view.md) 使用全部相关原照。单图也允许 AI 推演新机位和姿态，保持已知商品特征，标明无实拍覆盖的角度；不能因为生成图显得自然就把它当作新事实来源。内部接口、精确纹理和参数不从推演图取证。

每张图的说明包含图位目的、需要的原图、机位与摆放、景别和表现方式、不可改动项、推演范围、已确认文字和比例。不添加用户没要求的品牌或宣传词。

## 制作与核对

每个独立交付图位分别调用内置图片工具；无需凑成固定数量或拼图。所有轮次保留原始商品参考，上一版可以作为修改目标，但不能取代原图成为商品事实依据。

默认只快速对照原图看一遍，确认商品、数量、主要结构和关键文字没有明显错误。没有明显影响使用的问题就直接交付，不因细纹理、轻微光色差或“还能更好看”追加修改、反复放大比对或等待确认。**每个图位默认只生成一次，`max_renders: 1`；没有自动修正环节。** 细节无法判断仍保留 unknown，不影响整套候选交付。明确要求审图时才按 [审核](review.md) 展开详细报告。

只有用户明确要求修改时才制作对应的新版本，按其范围直接执行，不再索取同一授权，也不自行附加一轮微调。用户只改第二张，就不修改其他图；只改本次风格，就不更新品牌规范。发现错商品、缺失或多出部件、关键文案错误、严重变形等大问题，简短指出并保留问题状态，继续其余交付，不自动重做或停下等确认。旧任务剩余次数不触发修改。文件路径、预览链接等本地问题直接修复，不因此重新生图。

## 保存与续做

需要保存文件、多图交付、批量或续做时，用 [本地运行记录](runtime.md) 保存原图快照、事实、图位、输出与审核。脚本只做本地工作，不生成或编辑图片。Python 暂不可用时可按同一结构手工归档，不让本地辅助脚本阻止内置图像制作。

生成完成、AI 检查、用户选用是不同状态。AI 审核不能自动标记“卖家已选用”。只给用户需要的图、简短说明和可用链接；内部 JSON 与命令留在工作文件中。

没有实际图片输出就不能创建成功记录。文件存在但被替换、原图变化或计划变化时，不能沿用旧审核。恢复前查看任务状态，生成图未审核时先审核，不重新生成。

主入口套图的最终回复按 [交付格式](delivery.md) 呈现回复内图廊、完整 HTML 主入口、实际交付摘要和下载/文案链接。子技能依照实际范围采用其中适用部分，不扩展用户未要求的产物。

交付预览和打包用本地文件；不上传图片给第三方，不自动上架或发布。没有真实后台数据不宣称通过平台审核、A/B 胜出或提升销量。
