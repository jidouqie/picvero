# 原图对照审核

默认制作只快速对照原图检查一次，重点看错商品、数量或主要结构错误、关键文字错误、严重变形等明显影响使用的问题。没有大问题就直接交付，不反复放大追究纹理、轻微色光差异或一般审美偏好。一般细节差异不逐项打扰用户；无法判断的内容仍保留 unknown，不能改写为通过。

用户明确调用审图或要求逐项检查时，才展开下面的详细依据。已经看过的原图和完整成图无需重复打开；工具结果不能清楚查看时才补一次查看。单看候选是否自然不能证明商品没有变化。

## 五项记录

- identity：外形、数量、接口／把手／分隔等部件、色彩、图案和产品印刷。说明观察到了什么；细节无法比较时 unknown。多角度任务结合全部相关实拍核对；无实拍覆盖的推演面保留 unknown，合理视角变化本身不判作变形，记录中区分已见特征与推演部分。
- text：原商品上的文字是否保持；新增文案是否准确可读；翻译是否保留型号与数字。
- claims：画面及文字中的容量、尺寸、材料、性能和包含物是否有依据。
- visual：边缘、光影、透视、遮挡、手部，以及视觉主次、文字层级、对齐和留白。对品牌／营销任务，结合 [视觉设计](visual-direction.md) 判断布景与版式是否达到任务要求；画面自然不等于设计已经充分。
- usage：核对已经明确的用途和规则范围。没有平台信息可说明本次为通用候选；不能推断某平台一定允许。

每项 status 只能为 pass、fail、unknown、not_applicable，附实际 evidence。identity 和 visual 不能不适用。not_applicable 必须说明为什么。不要提交模板原文或仅写“看起来没问题”。

脚本只验证记录结构与版本，不能判断模型有没有真的看图。要实际使用查看工具；不能为通过程序而编造检查证据。

## 结果与后续

成套任务另按 [套图检查](marketplace-suite.md) 的“完成后按整套检查”部分查看图位分工、参考风格落实、缩略阅读层级与证据对应。相应问题写入本次整套说明和相关图片的 visual/text/claims 项；运行器不替代这项视觉判断。不能因单张漂亮就把重复口号、无依据数据或错位局部图判为合格套图。

任一 fail → needs_revision；没有 fail 但有 unknown → inconclusive；全部适用项通过 → reviewed_candidate。三个结果均不同于卖家确认选用。

检查不触发修正或新一轮等待。小问题直接随结果交付，大问题简短指出，保留真实状态并继续其他图片与文案；只有用户明确要求修改才按 [共用约定](workflow.md) 处理。状态名 needs_revision 表示发现问题，不是执行修改的指令。没有参考证据造成的 unknown 不靠生成次数解决。用户明确选用某版时可记录选择，但保留原检查结果。

使用 [运行记录](runtime.md) 的 review-template 取得候选和全部参考的哈希，填入证据后执行 review。更换了候选文件、原图或品牌计划后不能复用旧审核。

## 本地规格检查

inspect 只测文件元数据；系统有 Pillow 时还会做只读解码与透明像素检查。没有 Pillow 时它会明确输出 not_checked，不是失败，也不是已验证透明。

check 读取用户或项目提供的规格 profile。支持尺寸、字节上限、格式、精确比例和不透明要求；其他规则返回 unknown。profile 需要 name、scope、basis、checked_at。项目要求不能冒充官方平台要求。

背景纯白、主体占比、商标授权、平台是否实际接受等，不在首版自动确认范围内。
