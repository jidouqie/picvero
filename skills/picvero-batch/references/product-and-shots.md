# 商品资料与逐图策划

每个商品保留：SKU、名称、参考图角色、可见特征、用户确认参数、未知项、不可改动项。提炼能说明来源的卖点；外观推断与可发布事实分开。

## 图位选择

套图先读 [实际电商套图](marketplace-suite.md) 和 [多角度与多图参考](multi-view.md)，为各图位写明买家问题、核心信息、依据与视觉表达。运行记录的字段仍沿用下述结构；更完整的视觉计划可另存本次策划文件。

| 图位 | 画面任务 | 需要的依据 |
| --- | --- | --- |
| packshot | 清楚展示售卖商品 | 原图与包含物；按用途选择背景 |
| scene | 表达真实使用环境 | 该商品可见外观与合理尺度，不虚构功能 |
| feature | 一张强调一个重点 | 已观察或确认的卖点 |
| detail | 展示已有细节 | 原图可见区域或细节图，不能补造纹理 |
| size | 尺寸与参数 | 原始参数表；不能看图猜测 |
| localized | 替换说明文案 | 原文、目标语言和不翻译项 |
| tryon | 试穿／佩戴候选 | 产品图与明确任务，检查结构和尺度 |
| combination | 多件搭配 | 哪些出售、哪些只是道具需明确 |

未指定数量时采用 [整套交付](launch-kit.md) 的五个图位：主视觉、纯净展示、核心特点、场景、设计解析／购买信息。`id` 按用途分别命名，`kind` 可复用现有类型，例如主视觉与纯净展示都用 packshot，两个特点图都可用 feature。用户给了数量和类型就遵从；资料不足的图位调整为可见设计特征，不虚构功能或未知细节。

同一个标题或卖点不需要每张重复。保留标签与型号的准确性比制造复杂背景更重要。场景图中的道具不能使人误以为全部包含在售卖套装里。

## 平台与风格

制作场景、主视觉、特点页，或用户要求更高级、更有品牌感时，读取 [电商视觉设计](visual-direction.md)。把配色、空间、灯光与排版形成具体方案；基础展示图与营销主视觉按用途分别设计。

平台约束、平台建议、项目默认值分别记录。平台未知时交付通用候选，不声称平台专属。需要当前规则时通过宿主可用检索查看官方来源，记录站点／类目／图位／日期；离线时明确使用的版本。

品牌图中读取构图、留白、色调和光线方法，独立创作，不直接复制竞品的商标、评价和促销事实。

## 输入示例

```json
{
  "schema_version": 1,
  "label": "A001 上新素材",
  "brand": {"background": "浅色、干净", "tone": "简洁"},
  "products": [{
    "sku": "A001",
    "name": "桌面收纳盒",
    "references": [{"id": "front", "role": "product", "path": "product.png"}],
    "facts": [{
      "id": "compartments",
      "value": "三个分隔收纳空间",
      "status": "observed",
      "source": {"kind": "image", "ref": "front"}
    }],
    "invariants": ["分隔数量和标签保持原样"],
    "shots": [{
      "id": "main",
      "kind": "packshot",
      "goal": "干净背景展示原商品",
      "text": [],
      "fact_ids": ["compartments"],
      "aspect": "1:1",
      "max_renders": 1
    }]
  }]
}
```

事实来源 kind 为 user、image、document 或 unknown。image 和 document 的 ref 必须对应 references 的编号；unknown 事实不能被图位作为已知事实引用。例子只是结构示范，实际数据必须来自用户素材。
